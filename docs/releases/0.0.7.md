## Updates, Replacements, and Deletes

SinterDB 0.0.7 completes the basic CRUD surface.

### Highlights

- `updateOne()` and `updateMany()` with `$set`, `$unset`, `$inc`, `$min`,
  `$max`, `$push`, `$pull`, and `$addToSet`.
- `replaceOne()`, `deleteOne()`, and `deleteMany()`.
- Upserts for updates and replacements. The new document starts from the
  filter's equality fields and keeps an `_id` given in the filter.
- `UpdateResult` and `DeleteResult` with `matchedCount`, `modifiedCount`,
  `upsertedId`, and `deletedCount`. `modifiedCount` only counts documents that
  actually changed.
- Typed `UpdateFilter<TDocument>`: `$inc` is only offered for numeric fields and
  `$push` only for array fields, with value types checked.
- `_id` is immutable. Updates and replacements that try to change it are
  rejected.
- `updateMany` is all-or-nothing. If one document fails, none are changed.

### Wire protocol

- New commands: `updateOne`, `updateMany`, `replaceOne`, `deleteOne`, and
  `deleteMany`.
- New error codes: `InvalidUpdate` (4002) and `ImmutableId` (4003).
- The protocol document now includes a command reference.

### Changes to be aware of

- The exported `findOptions` interface is now `FindOptions`.
- Two operators in one update cannot target the same or overlapping paths.
- `deleteMany({})` and `updateMany({}, ...)` affect every document.
  `deleteOne()` and `deleteMany()` require a filter argument.
- Test files are now type-checked as part of `pnpm typecheck`.

### Notes

- All data is still held in memory. Durable storage and recovery arrive in
  0.0.8.
- `$setOnInsert`, `$rename`, and `$push` modifiers such as `$each` are not
  supported yet.
