## Filters and Cursors

SinterDB 0.0.6 adds multi-document queries with server-side cursors.

### Highlights

- `find()` returns a `FindCursor<TDocument>` that supports `for await...of`,
  `next()`, `hasNext()`, `toArray()`, and `close()`.
- Results are delivered in bounded batches. Cursors are tied to the connection
  that opened them, expire after ten minutes idle, and are released when the
  connection closes.
- Filter operators: `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`,
  `$exists`, `$not`, `$and`, `$or`, `$nor`, plus dotted nested-field paths.
- `sort`, `skip`, and `limit` options, with deterministic ordering across mixed
  value types.
- Typed `Filter<TDocument>` and `Sort<TDocument>` APIs.
- `listDatabases()` and `listCollections()` on the driver.
- `SinterServer.stop()` now force-closes connections that do not close within
  five seconds.

### Fixes

- Compatibility errors are now raised for `UnsupportedCapability` handshake
  failures.
- `-p` is documented in the server help text.
- Server, CLI, and driver documentation refreshed.

### Notes

- New wire error: `CursorNotFound` (code 5000).
- `InMemoryCollection.find()` now validates its options eagerly instead of on
  first iteration.
- All data is still held in memory. Updates and deletes arrive in 0.0.7.
